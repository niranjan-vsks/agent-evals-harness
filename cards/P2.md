## §2 WHAT THIS IS

The abstraction proof and the measurement instrument. The minimal loop is written against
a contract it had no part in shaping; the conformance suite is the judge of whether the
contract held. The graders and the task set are what the statistics in P3 will consume,
so their correctness is the eval methodology.

## §3 THE DESIGN IDEA

2 adapters, 0 shared lines, 1 suite. Graders are harness-blind: they see the final
response, the workspace and the trace event list, nothing else. The judge sees output,
not trajectory. The task set is built so the memory axis has 6 tasks that cannot be
solved without memory, 2 that memory could spoil, and 14 that memory should not touch.

## §4 DATA

No schema changes. Grader results use `grader_result` (DATA_MODEL 2.10) with
`judge_model_id` and `judge_prompt_hash` NOT NULL for `llm_judge`. `judge_label` and
`judge_validation` rows are written by the CLI commands in §6. Task JSON schema (validated
by `tasks:lint`, `api/src/tasks/schema.json`):

```jsonc
{"id":"^[a-z]+-[0-9]{2}(-[a-z0-9-]+)?$","version":1,
 "category":"memory_dependent|memory_distractor|neutral_deterministic|neutral_judged|honesty",
 "prompt":"string, ends with the FINAL: instruction for exact_match tasks",
 "fixture_dir":"fixtures/<id>"|null,"memory_fixture":"team-memory-v1"|null,
 "graders":[...DESIGN.md 7.3...],"discriminates":["memory"|"model"|"harness"|"skills"],"tags":[]}
```
Integers only; no floats anywhere in task JSON (hash agreement, P1 §4).

## §5 THE HARD PART

Graders that are wrong in the agent's favour or against it silently. An `exact_match`
that fails on trailing whitespace, a `unit_test` whose hidden tests the agent could see,
a judge that passes a generic release checklist for `mem-06`. Every grader gets a
negative test (a plausible wrong answer must fail) and a positive test (the reference
answer must pass), and the judge rubric criteria for `mem-06` are tested against a
generic checklist that must FAIL.
