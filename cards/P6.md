## §1 WHAT IS ALREADY TRUE

- Traces have `tool_call` events with `tool` (platform name) and `args`, `tool_result`
  with `is_error`, `api_call` with status, `memory_read`, and `exit_reason` on the trial.
- `grader_result.details` for `exact_match` contains `extracted` and `expected`; for
  `unit_test` the pytest tail; for `llm_judge` the criteria array; `judge_label` rows
  exist for 30 trials with `human_passed`.
- The compare payload is produced by the pure `compare.ts` (P3); extend it, do not fork it.

## §2 WHAT THIS IS

A cause for each failure, so a regression on a task points somewhere.

## §3 THE DESIGN IDEA

Rules, in a fixed order, first match wins. Each rule names the evidence it used, so the
category is explainable from the trace in the UI the same way a grader result is.

## §4 DATA

New enum `failure_category` and nullable column `trial.failure_category` plus
`trial.failure_evidence jsonb` (the matched rule and the event seq or grader index it
used). CHECK: `failure_category IS NOT NULL` iff `status = 'done' AND passed = false`.
Computed at ingest for new trials and by `npm run failures:backfill` for existing ones.

Categories and rules, in order:

| order | category | rule |
|---|---|---|
| 1 | `step_exhaustion` | `exit_reason = max_steps` |
| 2 | `timeout` | `exit_reason = timeout` |
| 3 | `hallucinated_tool_args` | any `tool_result.is_error` whose output matches a known arg-validation pattern (`No such file`, `not found`, `invalid argument`, JSON parse failure) AND the next assistant message repeats the same tool with the same args |
| 4 | `wrong_tool` | a `trace_check` grader failed on `tool_called` or `tool_not_called` |
| 5 | `tool_error_unrecovered` | the last `tool_result` before the final answer has `is_error = true` |
| 6 | `no_final_answer` | `final_response` is empty or has no `FINAL:` line on an `exact_match` task |
| 7 | `gave_up_early` | `steps ≤ 2` AND no `tool_call` event AND the task has a fixture_dir (the agent answered without looking) |
| 8 | `grader_disagreement` | an `llm_judge` grader failed AND a `judge_label` for the trial says `human_passed = true` |
| 9 | `memory_ignored` | task category `memory_dependent`, config memory `seeded`, a `memory_read` event exists, and the expected answer string does not appear in `final_response` |
| 10 | `wrong_answer` | everything else |

## §5 THE HARD PART

Rules that look right on the 3 trajectories you have seen and misfire on the rest. Each
rule gets a positive synthetic trace and a negative one (the nearest non-matching case),
and the backfill prints a category histogram per config that the builder sanity-reads
against 5 random trials per category before marking done.

## §9 STOP CONDITIONS

- A rule needs the judge or any model call. Stop; that is out of scope by design.
- More than 50 percent of failures land in `wrong_answer` after backfill. Report the
  histogram; do not add rules without an architect decision.
