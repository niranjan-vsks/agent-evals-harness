## §2 WHAT THIS IS

The control plane's reason to exist: run every task under every config N times without
corrupting results, then answer "A vs B, how sure" with the rule in DESIGN.md 9.4
applied by code.

## §3 THE DESIGN IDEA

An in-process scheduler loop (every 2 s) that dispatches `pending` trials up to
`MAX_CONCURRENT_TRIALS`, with every state change written to the DB before the next
action, so an API restart loses nothing but an in-flight HTTP call, which orphan recovery
re-queues. Statistics are pure functions over `done` trials, seeded, versioned, and
stored with their inputs on `comparison_run`.

## §4 DATA

No new tables. Columns already present: `trial.heartbeat_at`, `experiment.pause_reason`,
`trial_attempt.*`, `comparison_run.*`. Status transitions allowed (enforce in
`api/src/experiments/transitions.ts`, pure, tested):

```
experiment: draft -> queued -> running -> completed | partial | cancelled
            running -> running (paused: pause_reason set, no dispatch) -> running (resume)
            completed | partial -> running (extend to N)   [only via extend]
trial:      pending -> running -> done | errored | pending (retry)
            pending -> cancelled ; running -> cancelled
```

Retry policy table (pure, `api/src/scheduler/retry-policy.ts`):

| error_class | retryable | backoff before re-queue |
|---|---|---|
| rate_limited, provider_error, worker_crash, orphaned | yes, while attempt_count < 3 | 30 s, 60 s, 120 s |
| grader_error | yes, once | 10 s |
| backpressure | yes, does not count as an attempt | 5 s |
| config_invalid, cancelled | no | |

Circuit breaker: 5 consecutive terminal errors (attempts that ended `errored` with a
non-retryable class or exhausted retries) across the experiment → `pause_reason` set,
dispatch stops for that experiment; `POST /experiments/:id/resume` clears it.

Orphan recovery at boot and every 60 s: `trial.status = running AND heartbeat_at <
now() - (settings.timeout_seconds + 180 s)` → attempt `orphaned`, trial `pending`
(counts as an attempt).

## §5 THE HARD PART

Double dispatch and corrupted status. 2 scheduler ticks must never dispatch the same
trial (claim with `UPDATE ... WHERE status = 'pending' RETURNING`, 1 row or nothing).
An experiment must never read `completed` while a trial is errored (D-8 trigger plus the
derivation function). A comparison must never silently include errored trials or an
unvalidated judge.

## §8 GATES

1. Harness: `npm test` N of N. Required scenarios against the fake worker:
   (a) 2 configs × 4 tasks × N=2 runs to `completed`, 16 trials, every trial has exactly
   1 attempt; (b) a `-429` task is retried with backoff and ends `done` after the fake
   succeeds on attempt 2; (c) a `-crash` task that never succeeds ends `errored` after 3
   attempts and the experiment ends `partial`; (d) a `-400` task is `errored` after 1
   attempt; 5 such tasks in a row pause the experiment; resume continues; (e) kill the
   scheduler mid-dispatch (simulate by marking a trial running with an old heartbeat),
   boot recovery re-queues it; (f) extend from N=2 to N=3 adds exactly 8 trials with
   index 2; (g) cancel marks pending trials cancelled and the experiment `partial`-safe
   `cancelled`; (h) `compare` on (c) reports `n_excluded = 2` and `reliability: partial`;
   (i) `compare` with no `judge_validation` row excludes judge tasks and says so;
   (j) `pilot` payload contains no key named delta, rate_a or rate_b (test by key scan).
   Mutation test: remove the `WHERE status = 'pending'` from the claim and show scenario
   (a) double-dispatches; restore; record.

## §10 OPEN QUESTIONS

1. Scheduler tick interval and heartbeat. Default: tick 2 s; heartbeat written at
   dispatch and every 30 s while the HTTP call is in flight (a timer, since the call
   blocks); orphan threshold `timeout_seconds + 180`.
2. Bootstrap percentile method only, or also BCa? Default: percentile only; name it in
   the payload (`"ci_method": "percentile"`).
3. Per-task CI: resample trials within task (N vs N) with the same R. Default: yes, R =
   2,000 per task to keep the endpoint under 2 s; aggregate uses 10,000.
4. Compare endpoint caching. Default: recompute each call, store a `comparison_run` only
   when `?persist=1` or when an export is requested.
5. Reproduce endpoint semantics. Default: new draft experiment with the same
   config ids, task (id, hash) pairs, n_trials, axis and hypothesis, new seed; refuses
   with a list if any task hash is no longer in `task` or the worker's harness version
   differs from `worker_manifest`.
