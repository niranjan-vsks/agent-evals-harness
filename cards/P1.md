## §2 WHAT THIS IS

The skeleton every later phase hangs on: the compose stack, the full database schema
with its invariants, the model and harness registries, task sync with content hashing,
immutable configs, the worker's subprocess runner with its timeout and trace-assembly
guarantees, the Hermes adapter built against the frozen contract, and 2 graders. The
output is 1 real trial, inspectable as a trace row.

## §3 THE DESIGN IDEA

Every trial attempt is a fresh child process in the worker with its own directory; the
adapter streams events to disk; the runner owns time and assembles the result from disk.
The API owns identity (hashes) and never talks to a model. Stated once here so the builder
does not move grading into the API or run Hermes in-process in the worker server.

## §4 DATA

Create every table, enum, CHECK, partial index, rule and trigger in DATA_MODEL.md in
this phase, in Prisma plus 1 raw SQL migration for what Prisma cannot express:
- D-2 partial unique index on `task(id) WHERE is_current`.
- D-3 `CREATE RULE config_no_update AS ON UPDATE TO config DO INSTEAD NOTHING`.
- D-8 trigger on `experiment` rejecting `status = 'completed'` when an `errored` trial exists.
- D-9 trigger rejecting a decrease of `experiment.n_trials`.
- D-10 trigger rejecting changes to `hypothesis`/`axis` when old `status != 'draft'`.
- D-11 CHECK `((status = 'done') = (passed IS NOT NULL))`.
- D-13 CHECK `(status <> 'errored' OR error_class IS NOT NULL)`.

Each gets a test that attempts the forbidden write and asserts rejection.

Hashes, implemented once each:
- `api/src/common/canonical-json.ts`: keys sorted recursively, no whitespace, UTF-8, no
  float formatting concerns because inputs are validated to contain only integers and
  strings (task JSON) or are TS-only (config settings; `temperature` is a number, JS
  `JSON.stringify` formatting is the canonical form for configs).
- Task hash (TS in `api/src/tasks/hash.ts`, Python in `worker/task_hash.py`, must agree):
  `sha256( canonical(task JSON minus "version_hash") + "\n" + for each fixture file sorted by
  POSIX relative path: path + "\0" + sha256hex(bytes) + "\n" )`. Python canonical form is
  `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`. Test vector:
  `tasks/_hashvector/task.json` plus `tasks/_hashvector/fixtures/a.txt`; the expected hash is
  computed once by the Python side, written to `tasks/_hashvector/expected.sha256`, and
  asserted by both test suites. `tasks:lint` rejects non-integer numbers in task JSON.

## §5 THE HARD PART

A trial that hangs, crashes or leaks. Concretely: a model call stalls and Hermes keeps
it alive for at least 60 s per attempt across 3 retries, because `run_budget_seconds`
does not abort calls (see §1), so only the runner kill at R-2 bounds the trial; a second
trial finds the first trial's memory file through the default `~/.hermes`
(`hermes_constants.py:51-58`); a command hits `_floor_block` (`tools/approval.py:1069`),
which ignores YOLO and returns blocked, a scored failure and not a hang. The runner
invariants R-1 to R-8 and adapter invariants H-2, H-3, H-7 exist for this phase. If any of
their tests cannot be written, that is a stop condition, not a thing to skip.
