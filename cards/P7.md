# P7: UI visual layer (polish only, no logic)

## §0 CLAIM THIS COLD

Read in this order: `STATE.md` sections 0, P4, P5, P6; this card; `web/src/views/*.vue`
and `web/src/components/*.vue` as they are. Do not read the API.

Scope boundary: `web/` only. Every view keeps its data flow, props, API calls, routes and
test ids. Vitest stays green with at most test updates for class names and markup. No
new features, no new endpoints, no change to what numbers are shown or how verdicts are
decided (the `intervalContainsZero` cross-check and the "payload inconsistent" guard stay
byte for byte).

Out of scope: charts beyond the existing 3 SVGs (restyle them, do not add), animation
libraries, a component library, auth, mobile layout beyond "does not break at 1024 px".

## §2 WHAT THIS IS

The same screens, made to look and feel like an observability product someone would pay
for: calm, dense, legible, consistent. A reviewer should understand a comparison in 5
seconds and find why a trial failed in 10.

## §3 THE DESIGN IDEA

1 design token file, consumed everywhere. Dark theme by default (it is a trace and
metrics tool, and dark reads as "observability" to the audience), light theme as a
toggle in the header, system preference respected on first load, choice persisted in
`localStorage`. Everything is CSS variables, so the toggle is 1 attribute flip on
`<html>` and no component knows which theme it is in.

Visual rules (put the taste in the card):
- Typography: 1 UI sans (Inter via Google Fonts, system-ui fallback) and 1 mono (JetBrains
  Mono, fallback `ui-monospace`) for ids, hashes, tokens, costs, trace content. Sizes 12,
  13, 14, 16, 20, 28 px only.
- Spacing scale 4, 8, 12, 16, 24, 32 px. Cards with 1 px borders, 8 px radius, no drop
  shadows in dark, soft shadow in light. Max content width 1,440 px, centered.
- Color: neutral surface ramp (3 levels), 1 accent, and exactly 4 semantic colors: pass
  (green), fail (red), noise/neutral (amber), info (blue). Verdict and status chips use
  semantic colors only; nothing else does.
- Numbers right-aligned in tables, tabular figures (`font-variant-numeric: tabular-nums`),
  intervals always as `x [lo, hi]` through the existing `Interval` component.
- Motion: 150 ms ease on hover and expand, 250 ms on the theme switch, a skeleton
  shimmer while a list loads. Nothing else moves. No fades on route change.
- Empty states say what to do next ("No experiments yet. Create one from 2 configs.").
- Every table row that leads somewhere is clickable in full, with a hover surface.
- Never: centered body text, more than 2 font weights, rainbow category colors, icons
  without labels, toasts.

## §4 DATA

No data changes. New file `web/src/styles/tokens.css` (variables for both themes),
`web/src/styles/base.css` (reset, typography, tables, cards, chips, skeleton), a
`useTheme()` composable in `web/src/lib/theme.ts` (read system preference, read and write
`localStorage["evals.theme"]`, set `data-theme` on `<html>`), a `ThemeToggle.vue` in the
header.

## §5 THE HARD PART

Restyling without changing behaviour. The risk is a "small cleanup" that drops a badge,
hides the judge-policy caveat, or changes the verdict sentence. Every caveat the P4 card
required above the numbers (reliability, judge policy, judge_confidence low, excluded
tasks, rate-limit count) must remain above the numbers and be at least as visible as before.

## §9 STOP CONDITIONS

- A restyle needs a change in `api/` or in any `.ts` file that is not `theme.ts` or a
  component. Stop and report.
- A Vitest test needs a change in an assertion about a number, a verdict, or a badge's
  presence. Stop and report; that is behaviour, not style.
