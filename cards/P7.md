# P7: UI visual layer (polish only, no logic)

## §0 CLAIM THIS COLD

Read in this order: `STATE.md` sections 0, P4, P5, P6; this card; `web/src/views/*.vue`
and `web/src/components/*.vue` as they are. Do not read the API.

Scope boundary: `web/` only. Every view keeps its data flow, props, API calls, routes and
test ids. Vitest stays green with at most test updates for class names and markup. No
new features, no new endpoints, no change to what numbers are shown or how verdicts are
decided (the `intervalContainsZero` cross-check and the "payload inconsistent" guard stay
byte for byte).

Out of scope: charts beyond the existing 3 SVGs (restyle them, do not add), animation
libraries, a component library, auth, mobile layout beyond "does not break at 1024 px".

## §2 WHAT THIS IS

The same screens, rebuilt to look like a premium observability product (think Langfuse,
Datadog APM, Vercel's dashboard): calm, dense, legible, consistent, with a clear visual
hierarchy and a few deliberate moments of delight. The current UI is unstyled HTML with
blue underlined links and default fonts; that is the thing being replaced. A reviewer
should understand a comparison in 5 seconds and find why a trial failed in 10, and should
feel they are looking at a product, not a form.

Before writing any code, the builder invokes the design skills available in this
environment, in this order, and applies them: `impeccable`, `ui-ux-pro-max`,
`high-end-visual-design`, `design-taste-frontend`. Where those skills and this card
disagree on a specific, this card wins; where this card is silent, the skills decide.

## §3 THE DESIGN IDEA

1 design token file, consumed everywhere. Dark theme by default (it is a trace and
metrics tool, and dark reads as "observability" to the audience), light theme as a
toggle in the header, system preference respected on first load, choice persisted in
`localStorage`. Everything is CSS variables, so the toggle is 1 attribute flip on
`<html>` and no component knows which theme it is in.

Palette reference: the company this is built for uses a near-black navy base, an
electric cyan-blue accent, white headlines and 1 soft blue-to-navy gradient. Match that
feel, not their logo (no third-party logos or wordmarks anywhere). Dark theme tokens:
background `#0b1220`, surface 1 `#111a2e`, surface 2 `#18233b`, border `#243049`, text
`#e6edf7`, muted text `#8b9bb4`, accent `#22b8f0` (hover `#5fd0ff`), accent gradient
`linear-gradient(135deg, #1a73e8 0%, #22b8f0 100%)` used only on the primary button and
the app-shell header underline. Light theme: background `#f6f8fb`, surface `#ffffff`,
border `#e3e8f0`, text `#0b1220`, muted `#5b6b85`, same accent. Semantic colors in both
themes: pass `#2ecc8a`, fail `#ff5c6c`, noise `#f5b942`, info `#22b8f0`, each with a
12 percent tinted background for chips.

Visual rules (put the taste in the card):
- App shell: a 56 px top bar with a text wordmark "Agent Evals" in the accent, nav links
  (Configs, Experiments) with an active underline, the theme toggle at the right. Page
  title row with a short subtitle in muted text. Content on surface cards.
- Typography: Inter (Google Fonts, system-ui fallback) for UI, JetBrains Mono (fallback
  `ui-monospace`) for ids, hashes, tokens, costs, trace content. Sizes 12, 13, 14, 16, 20,
  28 px only. Weights 400 and 600 only. Headlines tight (letter-spacing -0.01em).
- Spacing scale 4, 8, 12, 16, 24, 32 px. Cards with 1 px borders, 10 px radius, no drop
  shadows in dark, 1 soft shadow in light. Max content width 1,440 px, centered.
- Color: the surface ramp, 1 accent, and exactly 4 semantic colors. Verdict and status
  chips use semantic colors only; nothing else does. The big verdict on Compare and the
  PASS/FAIL on a trial are 28 px, semantic color, with a tinted pill behind them.
- Hero numbers: pass rates and the aggregate delta are shown as large numerals (28 px,
  tabular) with the interval beneath in muted mono. Numbers count up over 400 ms on first
  render (1 small composable, no library).
- Numbers right-aligned in tables, tabular figures (`font-variant-numeric: tabular-nums`),
  intervals always as `x [lo, hi]` through the existing `Interval` component.
- Motion: 150 ms ease on hover and expand, 250 ms on the theme switch, a skeleton
  shimmer while a list loads. Nothing else moves. No fades on route change.
- Empty states say what to do next ("No experiments yet. Create one from 2 configs.").
- Every table row that leads somewhere is clickable in full, with a hover surface.
- Never: centered body text, more than 2 font weights, rainbow category colors, icons
  without labels, toasts.

## §4 DATA

No data changes. New file `web/src/styles/tokens.css` (variables for both themes),
`web/src/styles/base.css` (reset, typography, tables, cards, chips, skeleton), a
`useTheme()` composable in `web/src/lib/theme.ts` (read system preference, read and write
`localStorage["evals.theme"]`, set `data-theme` on `<html>`), a `ThemeToggle.vue` in the
header.

## §5 THE HARD PART

Restyling without changing behaviour. The risk is a "small cleanup" that drops a badge,
hides the judge-policy caveat, or changes the verdict sentence. Every caveat the P4 card
required above the numbers (reliability, judge policy, judge_confidence low, excluded
tasks, rate-limit count) must remain above the numbers and be at least as visible as before.

## §9 STOP CONDITIONS

- A restyle needs a change in `api/` or in any `.ts` file that is not `theme.ts` or a
  component. Stop and report.
- A Vitest test needs a change in an assertion about a number, a verdict, or a badge's
  presence. Stop and report; that is behaviour, not style.

## §10 OPEN QUESTIONS

1. Font loading offline. Default: Google Fonts link with `font-display: swap`; system
   fallback is acceptable when offline.
2. Charts. Default: restyle the 3 existing SVGs with tokens; keep them.
3. Light theme contrast. Default: WCAG AA for text on surfaces in both themes; check the
   4 semantic colors against both backgrounds.
